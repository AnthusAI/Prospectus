# Prospectus Amplify backend review

`amplify/backend.ts` uses Gen2 `defineBackend({})`, `createStack('prospectus')` and custom CDK resources. Amplify owns backend deployment and frontend publication. No AppSync, GraphQL, identity pool, CodePipeline or custom frontend CloudFront stack is required.

Run `npm ci --prefix infra && npm run check --prefix infra` for local compilation, security assertions and a review-only CloudFormation template. It does not contact AWS or supply executable Lambda code. The deployed Gen2 entry requires `.artifacts/backend/bootstrap.zip` from `infra/scripts/build-backend.sh`, built from exact source-lock commits. No moving branch or dummy bootstrap can deploy.

The separate Amplify app must use the public MIT-licensed `AnthusAI/Prospectus` repository's reviewed proof development validation branch and the pinned x86-64 build image `public.ecr.aws/docker/library/node@sha256:c4d5523090a817b7aa86d2111241fdd4f66d1e27782b44160e6aa63b357ecb2d` (Debian bookworm, Node22.23.3; the default Amazon Linux image is insufficient for the musl package script). Configure SPA rewrite `/<*>` to `/index.html` with status 200 for non-asset routes, and connect only `prospectus.cyclotron.anth.us`. Backend resources are fixed to account 682849160744 / us-east-1.

`amplify.yml` compiles the source-pinned Rust Lambda and deploys Gen2 before building the frontend. `amplify_outputs.json` custom outputs generate the production Vite environment. Both backend and frontend therefore derive from the same reviewed repository commit and its source lock. GitHub CI validates that same source/build contract without AWS credentials; Amplify Hosting's GitHub connection performs publication. Proof branch auto-build must remain disabled until resource/IAM approval and the first verified release are ready.

Official references: [custom CDK resources](https://docs.amplify.aws/react/build-a-backend/add-aws-services/custom-resources/), [Amplify backend service role](https://docs.aws.amazon.com/amplify/latest/userguide/amplify-service-role.html), [nested subdomains](https://docs.aws.amazon.com/amplify/latest/userguide/to-manage-subdomains.html).

After `npm ci --prefix amplify`, run `npm run check:amplify --prefix infra` and `npm run synth:amplify-review --prefix infra`. The latter instantiates the same Gen2 factory as production with review-only CloudFormation artifact parameters, including its real Amplify branch-linking helpers. It writes `.artifacts/amplify-review` without uploading code or making AWS calls. Production `amplify/backend.ts` always requires the real compiled bootstrap.zip.

The public image was verified in an isolated container to provide curl/git/OpenSSH/bash/sh/Node/npm/apt as root, satisfying [Amplify custom build image requirements](https://docs.aws.amazon.com/amplify/latest/userguide/custom-build-image.html). No private image repository or Docker publishing grant is needed. `amplify/verify-scope.mjs` uses the AWS SDK to check build credentials, so the image does not need the AWS CLI.

No placeholder is created. Google admission links only a unique enabled local prospectus-members invitation, with no automatic membership/user creation. See [deployment review](DEPLOYMENT_REVIEW.md) for the exact rights and remaining live verification. Official references: [federated identity linking](https://docs.aws.amazon.com/cognito/latest/developerguide/cognito-user-pools-identity-federation-consolidate-users.html), [pre-sign-up trigger](https://docs.aws.amazon.com/cognito/latest/developerguide/user-pool-lambda-pre-sign-up.html).

It compiles the exact pinned local API, uses an empty disposable ordinary Kanbus folder, fresh unlogged loopback token and real Chromium flow; it disables traces/HTML reports, redacts failure output and cleans its own process/folder. It needs no GitHub secret or AWS grant.
